### Session pickup

**You own the resume point. Read the prior trail, do not redo it.**

1. **Locate the prior trail.** Start from the user-provided handoff, known prior session reference, scoped resume note, actual `agent://` result, known `history://` task transcript, accessible external transcript URL, or pushed branch. Read metadata and final messages first, then the relevant earlier decision points. Stay within the active workspace and the explicitly named prior work. Do not scan unrelated project sessions or private chats for a plausible match. Use OMP's project-scoped session discovery/resume surface for the main session, not a fabricated `history://Main` URI. `history://` is for known task sessions and is not a global main-session search engine.

   Read `omp://session.md` to distinguish persisted session state from prompt history and transient output. `omp://tools/task.md` documents saved child outputs and histories. A scoped `local://` URI may need its recorded resolved path or original session to recover after restart. Read a provided external URL with the available authenticated reader when needed, without navigating an unrelated browser tab or assuming a remote runtime can be resumed. If a supplied transcript is inaccessible, use the supplied branch and handoff evidence, state the missing history, and do not fabricate its decisions.

   Read and apply `skill://principle-guard-the-context-window` when the transcript is large. Keep the reduced timeline in the parent's scoped notepad. Narrow and page relevant sections inline first. If substantial independent research slices warrant delegation, use `scout` tasks with exact known transcript/path pointers and bounded scope, not a generic agent asked to invent the pickup plan. No child inherits the parent's conversation. Never give a child permission to search unrelated sessions.
2. **Reconstruct operational state.** Identify the actual repository, branch, worktree, base and head, what landed through targeted `git log` and base-to-head `git diff`, open parent-owned tasks, decisions, PR state, and any paused operation. The prior trail is authoritative input for intent, prior observations and decisions; resist re-deriving it. Distinguish reported completion from linked run evidence, and historical state from facts changed since the checkpoint. Preserve unrelated dirty work. An interrupted rebase, pending push, detached head, or uncommitted patch needs reconciliation before more edits, not a hard reset.

   Use `hub` list/jobs/ps only to discover current process-local agents, owned jobs and supervised processes. Send follow-ups only to known live or revivable non-isolated agents. A stored job ID may have expired, a completed isolated agent cannot be resumed, and registry identities are not guaranteed across session restart. Read its saved output/history when available; if more work is required, start a fresh scoped task with reconstructed context. A source branch, worktree path, PR and recorded SHA are recovery facts, not proof a worker is still alive.
3. **Diff done versus pending.** Compare shipped artifacts against the original plan and name the precise resume point. Do not repeat the prior reproduction or completed work merely to establish confidence from scratch. Reuse existing evidence for the same artifact. A passing self-report without evidence is not proof, but it is still an input to investigate rather than a reason to rerun everything. Only refresh facts that may have changed, evidence that is missing, or claims invalidated by a new patch, environment or dependency. Clearly label inherited versus newly observed results.
4. **Route the remaining work and select the verdict.** Read and apply the matching exact `skill://sky-mode/playbooks/<playbook>.md` or skill entry. Choose whether to continue execution, deliver a finished recommendation, ratify or override a prior conclusion, or postmortem a failed run. State the evidence for an override rather than erasing the earlier decision. Pickup's routing ends here; the selected playbook owns the remaining execution. Update only the parent's work tracking. Do not restart a child orchestrator, create a second coordinator, or assume prior publishing/merging permission exceeds the current user/repository scope.
5. **Verify inherited claims against the original goal on the real artifact.** Read and apply `skill://principle-prove-it-works`. Inspect the existing real-surface proof first. When it covers the inherited artifact and acceptance criteria, reuse it rather than redoing the reproduction. Where evidence is absent or stale, the routed playbook performs the smallest necessary current-artifact check and records why. A prior “passed” summary alone does not satisfy this step. Do not call a recommendation shipped, a PR merged, or a task completed based solely on another agent's status label.

**Reply:** where the prior agent stopped, what you inherited versus redid and why, exact resume point, selected route/verdict, and the outcome. Link only recovered or produced evidence. If the work remains blocked, name the missing prerequisite and the reachable work completed without pretending the pickup itself finished the original task.
