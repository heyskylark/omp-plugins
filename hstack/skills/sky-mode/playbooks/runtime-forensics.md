### Runtime forensics

**You own the diagnosis. Instrument the live process rather than theorizing from source.** The deliverable is a cited diagnosis, not a fix.

1. **Capture the live signal on the matching surface.** Read and apply `skill://control-cli` for a terminal process or `skill://control-ui` for browser or Electron behavior. Capture a CPU profile for a spinning process, a heap snapshot for a leak, or a CDP trace for a visual glitch. Produce a real artifact, not a guess. Identify the exact process or tab, workload, timestamp, revision when known, and capture settings. Preserve raw output in local artifacts and distinguish the symptomatic interval from startup or unrelated work. For an owned process use `hub` start with observed readiness, logs, send, and stop. Existing processes are not yours to restart or terminate merely because they can be inspected. Use OMP `xd://debug` for live program state, attach or launch with a supported adapter, and inspect threads, stack traces, scopes, variables, and breakpoint observations. It supports one active debugger session. For browser or Electron work, open a named handle with the Eval browser prelude and the correct CDP target. Observe it before acting. Use `tab.run` for custom live-page or CDP capture through the actual attached browser. A missing profiler or attach permission is a concrete limitation, not permission to invent a capture.
2. **Reduce the artifact to the decisive finding.** Identify the hot-path function, the retainer chain from a leaked object to a GC root, or the loop firing without input. Read and apply `skill://principle-guard-the-context-window`. Parse bulk artifacts in a `scout` for read-only extraction when their size warrants it, and retain the reduced finding in the main thread. Use a configured general task agent only for substantial diagnostic reasoning beyond extraction. Supply the exact artifact pointer, format, question, and required provenance. The parent owns the diagnosis and tracking. Children return actual `agent://` outputs with reduced data and artifact offsets or identifiers, not an ungrounded verdict. Use Eval or SQLite to compute on real captures without flooding context with the full trace.
3. **Prove the mechanism cheaply before believing it.** Make a prediction that distinguishes the leading hypothesis from alternatives. Use debugger breakpoints, watches, stack and variable inspection, or reversible CDP instrumentation in the running process. When justified and authorized, temporarily instrument or hotfix live code without reloading so state survives and the hypothesized mechanism can be isolated. Capture before and after signals under equivalent input. Instrumentation itself can perturb timing, retain objects, or change scheduling. Name that risk, use the least invasive probe, and remove temporary probes afterward. Read-only forensics means no lasting source fix, not permission for unrestricted live mutation. Do not mutate production, user data, or a logged-in session without authorization. Prefer a safe owned reproduction when a probe would be consequential. If the available probe cannot distinguish causes, preserve an inconclusive diagnosis and name the next discriminating observation.
4. **Map the finding back to source.** Cite the file, symbol, and line allocating, scheduling, or consuming the work. Use available LSP symbol intelligence to connect observed frames with source and `read` to inspect the implicated section. Distinguish runtime-generated or bundled locations from verified source mappings. A plausible source explanation without the live evidence is still a hypothesis. Retain provenance from raw capture through reduction, probe result, and source location. Release owned debugger or browser handles and stop only owned temporary processes when finished. Never dump full private sessions or sensitive heap contents into the reply.
5. **Keep the throughput checkpoint to one line.** `throughput checkpoint: n/a, read-only forensics`.

**Reply.** Signal captured, reduced finding, how the mechanism was proved, source location, and actual artifact paths. Clearly label uncertain, incomplete, or inconclusive findings. No fix unless asked. Once the cause is known and implementation is requested, hand off through `skill://sky-mode/playbooks/bug-fix.md` or `skill://sky-mode/playbooks/perf-issue.md`. Do not open a PR for a diagnosis.
