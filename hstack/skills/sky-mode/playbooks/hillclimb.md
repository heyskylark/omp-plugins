### Hillclimb

**You own the metric and the experiment's integrity. Supervise and review. Delegate substantial attempts.** This is sustained iterative improvement of one measurable thing against a target. A one-off fix belongs in `skill://sky-mode/playbooks/bug-fix.md` or `skill://sky-mode/playbooks/perf-issue.md`.

Core discipline is one change, one measurement, keep or revert. Never stack unmeasured changes or claim a win from code inspection. Read and apply `skill://principle-prove-it-works`.

1. **Ground the workload and architecture before choosing the metric.** Read and apply `skill://how` over the target. Name realistic dimensions that move the result, including data size, history, state, and concurrency. Select a case that reproduces the user's complaint. If none does, repair the reproduction rather than hillclimbing a proxy. Fix one primary metric, its unit, the direction that counts as better, and a checkable stop predicate pairing a target with a minimum attempt count. For example, at least 50 percent better than baseline and at least 10 iterations prevents one lucky early win from ending the run. Use the user's numbers when given. Otherwise agree the target and attempt floor before running. Record correctness constraints and relevant tradeoffs, such as memory or total work against interactive latency.
2. **Build the measurement harness, prove sensitivity, then freeze it.** Read and apply `skill://principle-build-the-lever`. Run contrasting realistic workloads and confirm the target reproduces the symptom while easier cases separate as expected. If the harness cannot distinguish them, revise the workload or metric. Freeze the command, inputs, environment, warmup, sampling, and aggregation once sensitive. One repeatable command must emit the metric from the real system. Use enough samples to clear noise, such as a median of N rather than one run. Record the baseline distribution, primary metric, and a green run of the relevant regression gate before changing code. Keep raw output and provenance in local artifacts. If a service is required, use `hub` start with explicit readiness, then logs, send, and stop under a stable owned process name. Process creation alone is not readiness. Do not silently change the harness mid-run. If correction is necessary, record a new baseline and make comparisons within that measurement regime.
3. **Open the decision log.** Read and apply `skill://show-me-your-work`. Keep a parent-owned `decision.tsv` outside the tracked tree, for example at a scoped `local://` path or a confirmed gitignored path. One row per attempt contains `id`, `hypothesis`, `change`, `before`, `after`, `delta`, `tests`, `verdict`, and `note`. Verdict is kept or reverted. Record incomplete attempts explicitly in the note rather than inventing measurements. Read the log before every attempt. The parent owns tracking and synthesis; children return evidence through their `agent://` outputs.
4. **Ground each hypothesis in the architecture model.** Name a mechanism, such as deferring a specific boot-path operation because it blocks first paint. Do not substitute an ungrounded suggestion such as trying memoization. Predict what the frozen measurement should show and name any correctness or resource risk.
5. **Loop with one hypothesis per iteration.**
   - Read and apply `skill://principle-guard-the-context-window`. Delegate substantial implementation to the configured general task agent with a tight scope. Use `sonic` only for mechanical edits and `scout` for read-only research. Review the resulting diff and evidence yourself. Keep a tiny attempt inline when delegation would add overhead rather than independent work.
   - When several substantial independent hypotheses are live, read and apply `skill://principle-separate-before-serializing-shared-state`. Define shared baseline and evidence format first, then launch them together in separate isolated workspaces. Competing alternatives must not auto-apply. Use Eval `agent()` with `isolated: true, apply: false, merge: false` where supported, or obtain non-editing proposed patches. Honor spawn and plan-mode limits and disclose constraints. Each attempt measures against the same baseline. Serialize resource-sensitive measurements when concurrent load would contaminate them. Re-measure combined accepted changes because independent wins need not compose.
   - Measure before and after with the frozen harness, then run the relevant regression gate. Delegated workers must skip shared gates during concurrent editing; the parent runs them at the stable measurement boundary before another iteration. Preserve command, revision, workload, sample summary, and artifact pointers.
   - Accept only a movement beyond noise with the gate green. Otherwise revert the attempt in full without touching unrelated user work. A tweak that might help does not stay. Missing output, a failed gate, or an inconclusive measurement is not a win.
   - When commits are authorized, make one commit per accepted fix, staging only the files it changed with explicit paths, never `git add -A`. Without authorization, retain the same ordered accepted units in the log and do not commit or push. Log kept and reverted rows alike.
   - Read and apply `skill://principle-sequence-verifiable-units`. Every iteration ends with its check before the next begins. For an unattended run, read `skill://sky-mode/playbooks/autonomous-run.md` and borrow only its native wake mechanism, not its stop rule. Use returned background results or `hub` waits for known events while the session is live. Do not imply that a wait schedules a future agent turn after the session exits.
6. **Push past the first plateau.** After several rejects, pivot category, combine promising near-misses into one newly measured hypothesis, re-read source, or try a more radical change before concluding the hill is climbed. Read and apply `skill://principle-laziness-protocol`. Correctness and simplicity outrank the number. Revert a numerical win that breaks behavior. Keep a simplification that holds the number when its value is explicit, and log it as a simplification rather than a metric improvement.
7. **Stop honestly.** Stop when the predicate is met, or when remaining ideas are marginal and not worth their cost. Do not relax the predicate to meet it or quit with cheap untried hypotheses remaining. If stuck or interrupted by a real limit, surface it rather than spinning. State whether the predicate was met and retain incomplete outcomes.
8. **Deliver accepted units in order.** When PR creation and its required external writes are authorized, read and apply `skill://sky-mode/playbooks/opening-a-pr.md` with accepted commits stacked in landing order. Otherwise return the local results without creating or pushing a PR.

**Reply.** Metric and target, baseline to final with units and percent delta, iterations run with kept versus reverted counts and incomplete attempts, each accepted fix on one line, the actual `decision.tsv` path, and the best next idea if pushed further. State final predicate status and any measurement or correctness limitations.
