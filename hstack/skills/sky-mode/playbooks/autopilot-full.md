### Autopilot-full

**You own the verdicts, never the PRs. One owner runs each PR from build to merge, and nothing merges without your clean swarm verdict.** Use for a queue of independent PRs and one-owner-per-PR programs. In `skill://sky-mode/playbooks/orchestrate.md`, the coordinator integrates verified work and workers never merge. Here the owner carries the lifecycle and the root retains verification, countersigns, and audits. Read and apply `skill://sky-mode`.

1. **Mark the operator's items and honor state-then-wait.** Items the operator names stay theirs. The operator reviews and clicks; no owner merges those items. A request to state the protocol or plan is not a go. State it and stop. On explicit go, record the full objective, done predicate, dependency graph, operator-owned items, and commit/push/PR/merge authority in the parent todo and `local://<program>/notepad.md`. Keep the objective across turns and explicit session resumptions. Generic autonomy grants no blanket external-write permission. Unapproved operations remain gates.
2. **Assign one owner per PR with the full lifecycle and an early trail.** Resolve the forge once. Default to `gh`; select Origin only after its installed help documents the required PR operations and it can resolve and support this repository. Use that documented interface consistently, never infer flags from the executable name. Otherwise record the `gh` fallback. Never require Graphite. An OMP implementation task owns build, authorized first push, ready PR, real-artifact self-proof via `skill://principle-prove-it-works`, skeptical review triage via `skill://sky-mode/references/bugbot-triage.md`, `skill://deslop`, `skill://no-comments`, authorized rebase onto current trunk for independent PRs, the explicit babysit phase from `skill://sky-mode/playbooks/babysit.md`, and authorized merge. A private dependent stack has one topology owner who preserves recorded parent tips bottom-up under the selected stack playbook, rather than rebasing every child onto trunk. Read and apply `skill://sky-mode/playbooks/opening-a-pr.md` for PR mechanics. This program explicitly requests babysitting after each owner's build; ordinary PR creation alone does not.

   Within about 15 minutes, each owner starts its `decisions.tsv` trail through `skill://show-me-your-work`, publishes the first authorized branch snapshot, and opens the PR ready, not draft. Open before self-proof so the URL, decisions, and checks form an early trail. If publication lacks authorization, save the local snapshot and report that gate rather than publish. Keep the trail uncommitted and return its artifact with reports. Rebase before babysit, not only when conflicts appear. Merge is the step the owner may never take alone.
3. **Run independent owners in true parallel and never stack unrelated PRs.** Scope inline first. Submit eligible independent substantial owners in one `task` batch with shared `# Goal`, `# Constraints`, and `# Contract`, and per-owner `# Target`, `# Change`, and `# Acceptance`. Use configured general task agents for implementation, design critique, evidence judgment and runtime proof with custom verdicts, and `scout` for research. A discovered specialist must fit both the assignment and its tools/output contract. Use bundled `reviewer` only for patch-introduced bugs anchored to changed diff lines, retaining its native findings/overall_correctness/explanation/confidence schema; use `security-reviewer` only for a compatible source-security slice in its own schema. A schema override cannot change a patch-only role's intent. No per-task model selection or invented role. Require one writer per branch and exclusive file ownership. Independent PRs branch from trunk. Dependent PRs use merge-then-branch. The one exception is a genuinely dependent split owned as a short private base-branch stack.

   Dispatch bounded waves under the actual task concurrency, job capacity, spawn policy, runtime and recursion limits. Queued work is not running. Use isolated workspaces for independent editing. Native `task` isolation can automatically apply patches or cherry-pick branch results, so use documented `eval agent(..., { isolated: true, apply: false, merge: false })` when acceptance must precede integration or when owner branches must stay separate. Preserve returned IDs and patch/artifact paths before workspace teardown; isolated agents cannot be revived. Full lifecycle ownership can span bounded tasks under one logical owner, with a consolidated brief, not a fictional persistent worker. Children have no conversation, receive explicit upstream `agent://` artifacts, do not own todo, and do not recursively invoke this orchestrator. Skip mid-flight project-wide validation; run gates on stable owned heads after the build wave.
4. **Swarm-verify every merge-ready head before merge.** Read and apply `skill://swarm`. At the exact merge-ready head SHA, partition independent verifier lanes and aggregate one verdict per PR. Lanes rerun required gates at that SHA, prove the load-bearing behavior live with `skill://control-cli` or `skill://control-ui`, and audit receipts and diff while distrusting the PR body. A regression lane runs the same scenario on current trunk. If trunk lacks the feature, record it and gate the diff-added behavior plus the user's awaited end state. Do not invent a trunk result. The live lane is the floor. A verdict without it cannot be clean. Use independent configured general task agents for these scenarios and custom proof judgments, optionally configured different-model agents when available; same-model independent runs are not cross-model corroboration. The root inspects full `agent://` outputs and receipts before normalizing lane judgments and any bounded native patch/security findings into the per-PR verdict. Native patch correctness alone never establishes runtime `PASS` or coverage. Findings return to the owner for fix-forward. A changed patch needs fresh verification.
5. **On a clean verdict, the authorized owner merges and takes the next eligible item.** The merge-ready report pins a trunk-current head. The root records verifier identities, evidence, head SHA, base SHA, stable base-to-head patch-id, and its clean verdict in `local://<program>/ledger.tsv`. If trunk moves, apply `skill://sky-mode/playbooks/shipping.md`. A new head voids the verdict unless the stable patch-id is unchanged; even then rerun current-head mergeability and CI. Only explicit merge authority plus the root's clean countersign permits an owner squash-merge through the resolved forge. Operator-owned and interaction-review-gated items stop at merge-ready. For any private dependent stack, only its contiguous verified run from the root is eligible. After confirmed merge, assign the next self-contained eligible item.
6. **Run the root layer.** A genuinely new raise of a pinned gate or budget value that CI only allows to tighten requires a fresh root countersign after verifier proof. Absorbing values already landed on trunk is drift, not a raise. Record the old value, proposed value, evidence, verdict head, and countersign.

   Audit all owners roughly every 30 minutes while the parent is active. Use a named `hub start` process with `application: "sleep"`, `args: ["1800"]`, then observe its exit with `hub wait` and rearm after the audit. Process creation is not readiness for services; their actual readiness must pass before use. Prefer real watcher events where available, with the timer as fallback. `hub` is supervision, not an agent scheduler: it does not wake a closed session into autonomous execution. Default processes stop after the last OMP client exits; persistence is opt-in, bounded by documented broker behavior, and does not preserve agent reasoning. On shutdown, write an exact pickup note and require an explicit resumed user session. Do not silently enable persistence.

   At each tick, re-read `skill://sky-mode/playbooks/autopilot-full.md` and the stored objective. If the repository supplies an updated playbook on trunk, inspect the actual known path and record the version instead of assuming the plugin lives in that repository. Audit both protocol and objective, fixing drift in that tick. Inspect `hub jobs`, known agent outputs, forge state, published refs, and report artifacts. A liveness probe is not a work reassignment. Message only known IDs when steering is needed; `hub send` may revive an idle agent. Count side effects, not reassuring prose: accepted artifacts, commits, authorized pushes, PR/check deltas. A lane past its expected runtime with no evidence is stuck. Stop or cancel it, reconcile its last artifacts and ownership, then dispatch a scoped replacement without waiting for a polite return. Collect all decision trails. When merges batch, run a retrospective and a post-merge bot-comment sweep. Send the operator a status message even if nothing changed.
7. **Stand down immediately on the operator's stop.** Send every known owner a zero-writes order, cancel work that cannot hold, and stop owned mutating processes. Do not delete work or roll back user changes. Retain briefs, artifacts, verdicts, and pending gates until explicitly released.

**Reply:** the queue with each PR's owner, state, and head SHA; each verdict and the swarm that produced it; what merged and what each owner took next; countersigns and their evidence; open operator gates; collected decision-trail paths; and any paused work with exact pickup instructions.
