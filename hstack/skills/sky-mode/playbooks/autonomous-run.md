### Autonomous run

**You own the exit condition. Define done, then drive to it without stopping.** This is one task driven to a predicate, not a standing program. Read and apply `skill://sky-mode` and `skill://show-me-your-work`.

1. State the exit condition as a checkable predicate before the first iteration. Examples include tests green, reproduction fixed, all N explicitly authorized PRs merged, or pixel-diff zero. Record the predicate, authority boundaries, initial evidence, and next action in the parent todo and a scoped `local://<run>/notepad.md`. Do not substitute a smaller target mid-run.
2. Pick the wake mechanism. For an event such as CI, a merge, or a ref advancing, run the actual watcher as a named `hub` process with `start`, observe readiness, and inspect its `logs` and `wait` outcome. Use a long heartbeat as fallback. Without an event, use a bounded time-based check sized to when the result is worth rechecking. A simple heartbeat can be a supervised `sleep` process, rearmed after its observed exit. `hub wait` for jobs returns on the first result or message, not every child. Wait only when there is no useful work. A timer does not invoke an agent turn. Keep the parent session active to consume it; after exit, continuation requires an explicitly resumed user session. Never promise autonomous work after the session stops. Record process names, next check time, and pickup instructions. Respect runtime limits and process teardown behavior in `omp://tools/hub.md`.
3. Each iteration makes the smallest change the evidence justifies and verifies it against the predicate. Read and apply `skill://principle-sequence-verifiable-units`. Verify each unit before the next rather than batching checks at the end. Commit an improvement only when authorized. Remove only this run's unhelpful experimental changes, preserving user work. A speculative safeguard that did not improve the result does not ride along.
4. Mid-run discoveries are yours within the authorized scope. Apply `skill://sky-mode` to blocking related bugs, flaky verifiers, review noise, tooling failures, orphaned follow-ups, and fixable drift. Separate out-of-band fixes into their own change or authorized PR. Do not park reversible in-scope work for the human. Surface irreversible actions, missing external-action authorization, genuine product or preference calls no experiment can settle, and real dead ends. Broad autonomy does not authorize commits, pushes, merges, installations, deletions, or sensitive external writes. Preserve the main predicate and return to it after each justified side fix.
5. Checkpoint every iteration with `skill://show-me-your-work`. Record what changed, the observed result, whether the predicate moved, accepted and discarded hypotheses, artifact paths, and the next iteration. Parent todo tracks execution; the decision trail retains completed history for pickup.
6. Stop when the predicate is met. A plateau calls for a new hypothesis or method, not a lower bar. Surface a genuine dead end instead of spinning. On an explicit hold, stop new work, send zero-writes instructions to every known owner, cancel jobs that cannot safely hold, and use `skill://sky-mode/playbooks/pause-safely.md`. For resumed work, use `skill://sky-mode/playbooks/session-pickup.md` and reconcile stored evidence with actual state before continuing. A runtime or authorization boundary is a reported stop, never a claim of completion.

**Reply:** the exit condition, iterations run, what landed or remains local, what was discarded, final predicate state, evidence and trail paths, and any real blocker or exact pickup action.
