# Worktree and simulator cleanup

**You own the disk and the safety gate.** Audit merged or abandoned Git worktrees and stale iOS simulators to reclaim space. Deletion is irreversible, so every step guards against deleting something in use or holding recoverable-only-here work. An audit request is not deletion authorization. Autonomy never overrides the user's protected paths or authorizes unrelated deletion.

1. **Snapshot and audit.** Record `df -h /` and, when worktrees live on another filesystem, that filesystem's free space too. Read and apply `skill://principle-build-the-lever` and `skill://principle-encode-lessons-in-structure`. Read the portable helper at `skill://sky-mode/scripts/worktree-audit.sh`, then run `bash skill://sky-mode/scripts/worktree-audit.sh` with the repository as cwd, or pass one explicit repository path. The Bash tool resolves the skill URI; in an ordinary terminal use the resolved installed script path. The helper is an audit, never a deletion command.

   The helper discovers paths from Git's worktree inventory rather than hand-typed folder conventions. A worktree may live outside the repository or under a harness-managed isolation root. Its TSV columns are `SIZE`, `AGE`, `MERGED`, `DIRTY`, `REMOTE`, `PR`, `LAST_CHAT`, `BUCKET`, and `WORKTREE`, sorted by size. Age reflects the HEAD commit, not proof of abandonment. The audit checks tracked/untracked/ignored state, ancestry, branch/remote information, and best-effort PR status. It does not fetch automatically; record reference freshness before using merge evidence. `LAST_CHAT` is unknown until explicitly scoped ownership evidence is added. Missing Git/PR/status information must remain unknown, not silently clean. Run a slow finite audit asynchronously through Bash when useful and keep its artifact rather than flooding context. Do not build a background transcript crawler.
2. **Treat buckets as advice, not permission.** Read and apply `skill://principle-prove-it-works`. An apparent `safe` candidate can still belong to an active or user-protected session. Obtain the user's protected/pinned/active worktree set where it is not already in scope. Cross-check the current repository/worktree, known task owners via `hub` list/jobs, supervised processes via `hub` ps/describe, and explicitly identified session artifacts. Unknown ownership holds a candidate. A closed PR is not a merged PR; an old commit or missing remote is not abandonment. A squash-merged PR can explain why ancestry says no, but its exact repository, branch, head, and merge state need verification.
3. **Verify use and preservation per candidate.** For a `verify-recent-chat` row or any doubtful candidate, first inspect the scoped evidence inline. Read and apply `skill://principle-guard-the-context-window`; batch `scout` agents only for multiple substantial independent ownership checks. Give each exact candidate paths and known relevant `history://<id>` or `agent://<id>` pointers, and require evidence for owner, ongoing/protected status, and every worktree it touches. A parent can have arena, reproduction, and other child workspaces whose names never appear in its title. Query a known owner through `hub` instead of mining its session files. Do not scan global private history, infer absence from an empty roster, or treat an unavailable transcript as inactivity. OMP history may omit unregistered top-level sessions, and an isolated child may already have been merged and cleaned by OMP; re-read Git inventory before taking action.

   For each path from the inventory, record canonical path, repository identity, branch or detached HEAD, exact HEAD, locked/prunable state, tracked changes, untracked filenames, ignored files, merge/PR evidence, remote/upstream and unique-commit preservation, known session/process owners, and protected status. Use `git status --porcelain=v1 --untracked-files=all`, appropriate ignored-file listing, branch/ref inspection, and focused diffs in that worktree. Quote paths or use argument arrays. Verify branch refs preserve the exact HEAD; detached or unpushed commits need an explicit preservation decision. A squash-merge marker alone cannot prove later local commits were included. Do not touch active OMP-managed isolation while its owning task is running.
4. **Pause on irreversible loss.** `wip:N` identifies tracked uncommitted edits. Show the focused diff and obtain a decision before removing them. A scratch/untracked count is not proof of disposability; name the files, inspect enough to classify them, and include them in the user's decision. Ignored build outputs may be disposable, but ignored files can also contain local databases, secrets, or expensive state. Enumerate and classify them before deletion. In-use, protected, locked, dirty, detached/unpreserved, unknown, or ambiguous candidates stay held. A clean, merged, not-in-use candidate may proceed only within an explicit cleanup authorization covering that exact set or clearly defined category. Obtain separate authorization for unrelated paths, simulator state, or caches. Record approval and preservation decisions in the cleanup ledger before mutation. Do not silently stash, reset, discard, force-unlock, or create a rescue commit as a substitute for consent.
5. **Prune only the confirmed set.** Immediately before each approved deletion, recheck inventory membership, canonical path, HEAD/branch, status including untracked/ignored files, ownership, and approval. A changed row returns to hold. Use `git worktree remove <verified-path>` without force first. If Git refuses, inspect why; do not escalate automatically. `--force` is reserved for the exact reviewed contents whose irreversible loss the user explicitly approved, never a blanket command. Branch refs are retained; do not delete branches as part of worktree cleanup.

   If a directory survives because of ignored build artifacts, inventory that exact remainder, verify it is the approved worktree and not a symlink or broader parent, and obtain authorization for any contents not already covered. Only then remove those named approved remnants. Never use blanket `git clean`, `git reset --hard`, or an indiscriminate recursive removal over a worktree root. Inspect `git worktree prune --dry-run` and prune only stale administrative entries whose ownership is resolved; do not erase references to temporarily unavailable volumes. Re-list Git worktrees and record `df -h /` and other affected filesystems after the confirmed removals. Keep failed removals separate from completed ones and retain every held path.
6. **Consider simulators and other reclaimers separately.** On a host with Xcode tooling, inventory devices, runtime IDs, sizes, and active simulator/test processes first. The targeted native commands include `xcrun simctl --set testing delete all` for the testing device set's XCTest clones, `xcrun simctl delete unavailable`, and `xcrun simctl runtime list` followed by `xcrun simctl runtime delete <verified-id>` for a specific old runtime. These are deletion recipes, not a default batch. The testing-set command deletes the whole set; use it only if every member is confirmed unused and the user approved the whole set. Hold active or uncertain devices and runtimes. Do not shut down someone else's test run to make a candidate eligible.

   Other potential reclaimers are Xcode `DerivedData`, `iOS DeviceSupport`, explicitly identified application backup/snapshot stores, and pnpm, uv, brew, or yarn caches. Inspect the actual installed application's paths instead of guessing a desktop runtime's private storage layout. Never classify OMP sessions, memory, credentials, blobs, or live artifacts as disposable cache. Keep the original source's backup/snapshot-store check as a category, not a command to delete an application profile. Use supported cache-management commands after reading the installed tool's documentation and obtaining scoped approval. Never clear anything the user said to keep. On a host without simulator/cache tooling, report that portion as unavailable and finish the reachable worktree audit.

This playbook deletes user state without a code review to catch a slip. The inventory, ownership proof, preservation decision, authorization, and final recheck are the review.

## Cleanup ledger

Maintain one row per candidate, including simulator/runtime/cache candidates when relevant. Record path or device/runtime ID, size, age basis, repository/branch/HEAD, tracked/untracked/ignored details, merge and PR evidence with freshness, remote/unique-commit preservation, known owner and protected/in-use evidence, proposed bucket, approval scope, action taken, result, and one-line hold reason. Keep the audit artifact and before/after disk readings. Do not put secrets or unrelated transcript contents into the ledger.

## Reply

- `df -h /` before and after, other affected filesystem readings, and observed space reclaimed. Explain that concurrent disk activity can affect the measured delta.
- Worktrees actually pruned, with their retained branch/HEAD references and approved removal evidence.
- One-line reason for every held candidate, naming the known owning session/process or the uncommitted, untracked, ignored, unpreserved, or unknown state.
- Simulator/runtime/cache deletions separately, including approved scope and unavailable tooling.
- Any failed operation or inaccessible ownership/PR data, without claiming it safe.
