### Pause safely

**You own a clean stop. Leave a checkpoint a cold-start agent can resume from.** This is explicit. “Keep going”, “going to bed, keep going”, or “don't stop” is not a pause request. An impending restart or compaction warrants a checkpoint, not silently abandoning an authorized run.

1. **Stop at a safe boundary.** Finish the current atomic step or back out only your incomplete change without discarding unrelated edits. Start nothing new. Do not leave a known-broken mid-edit state when a safe completion is available. Coordinate a clean stop with known active children through `hub` send, ask them to return their partial result and changed-file/patch facts, and cancel only owned unfinished jobs when necessary. Do not equate cancellation with durable work. Isolated workspaces may be cleaned at completion, so preserve returned patches or integrated changes before relying on a checkpoint. Stop owned supervised processes with `hub` stop when safe. Do not kill another actor's process or assume an in-flight external operation was cancelled; record and reconcile its actual state.
2. **Take no irreversible action merely to pause.** Do not open a PR or introduce a first push for checkpointing. An existing PR or pushed branch is not blanket permission for another push, merge, force-push or deployment. Preserve all user/repository authorization boundaries. Do not delete a worktree, reset a branch, or change stack topology as a stopping shortcut.
3. **Make the work durable.** If commits are authorized, checkpoint task-owned uncommitted edits as one clear `wip:` commit on the current branch. State in the body when the tree remains broken and why. Do not sweep unrelated staged or unstaged work into it. If commits are not authorized, leave the files intact and record their exact paths, branch/base facts and dirty state; preserve a task-scoped patch or artifact where needed without replacing the original files. Distinguish tracked changes, untracked assets, generated evidence, and work still held only by a child. Never claim a clean tree, saved patch, successful commit or persisted session without evidence from the actual operation.
4. **Write the resume note off-context.** Use a parent-owned scoped `local://<task>-resume.md` checkpoint, or a known durable project-approved handoff location when a new session must find it. Include its resolved location in the reply when available. A scoped local URI alone is not a universal cross-session locator. Record intent, current atomic step, completed work, verified versus merely reported claims, branch/worktree/trunk/base/head facts, PR URLs and frozen stack order, current dirty state, decisions, pending tasks, key files, gotchas, permissions, live processes and their disposition, and the first next action. Name only observed `agent://`, `artifact://`, and known `history://` references. If a decision trail from `skill://show-me-your-work` exists, point to it instead of duplicating it. For compaction, write this checkpoint before losing the current context, then continue if the user asked to keep going.

OMP's session history records completed messages and tool results, not an unsaved reasoning state. Read `omp://session.md` for persistence guarantees. Do not hand-edit session JSONL or assume streaming partial output survived. Read `omp://tools/task.md` for child lifecycle and `omp://tools/hub.md` for cancellation and process supervision. Job IDs are short-lived, isolated agents are not revivable after completion, and process names require rediscovery after restart. Save branch, file and artifact facts as the durable recovery basis rather than promising to resume an old ID.

**Reply:** current point in the workflow, what is on disk versus still unrecorded, checkpoint and evidence paths without diff dumps, commits actually made, whether the tree is clean or dirty, child/process disposition, and the first action on resume. This is a pause, not a final success report. Resume through `skill://sky-mode/playbooks/session-pickup.md`.
