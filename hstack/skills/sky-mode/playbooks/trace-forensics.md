# Trace forensics

**You own the diagnosis from the artifact. Load it, shape it, narrow to the cause, attribute to source.**

Distinct from `skill://sky-mode/playbooks/runtime-forensics.md`, which instruments a live process. Here the capture already exists. It is a fixed dataset. Read it; do not re-run the workload or silently substitute a fresh capture. Keep tooling portable. Use a compatible DevTools/trace parser for `.cpuprofile` and compressed `.json.gz`, a scoped text reader for a spindump, and format-aware heap tooling for a `.heapsnapshot`.

1. **Identify the format and load it with the right tool.** Record the supplied artifact path, size, capture metadata, compression, clock units, process/thread identity, and available build/symbol information. Preserve the original and operate on derived files. Read and apply `skill://principle-guard-the-context-window`. Scope the header and format inline first. For genuinely large independent artifact slices, batch `scout` research agents with exact artifact pointers and bounded questions. Keep reduced findings in the parent, not raw traces. If there is only one manageable dataset, use a local parser directly rather than delegating a trivial slice. Children have no conversation history; give scope, schema, evidence requirements, and a no-fix/no-recapture boundary. Honor available tool, spawn, and context limits rather than claiming a complete scan when one was capped.
2. **Transform the artifact into a queryable shape before reading the bulk.** Use an installed compatible parser or an Eval Python/JavaScript transformation to create a scoped SQLite database with one row per sample, frame, event, heap node, or edge as appropriate. Keep stable source IDs, parent/caller links, timestamps and units, thread IDs, byte counts, and symbol mappings so every aggregate can be traced back. Preserve heap edge types and node metadata needed for retainers. Record parser version, conversion recipe, counts, and unsupported or dropped records. Query the derived SQLite file with `read` selectors or SQL; do not paste a giant JSON payload into the conversation. A text spindump may instead use a reduced thread/frame/wait table that retains original line ranges. Failure to decode a format is a named prerequisite, not evidence that nothing is wrong.
3. **Narrow to the cause.** For CPU/time, rank frames by self and inclusive time and walk the caller tree to the hot path. Distinguish sampled time from elapsed duration and CPU from waiting; do not sum inclusive ancestors as independent work. For leaks, follow the retainer chain from the suspect object to a GC root, preserving the actual strong/weak edge semantics and retained versus shallow size. For a spindump, identify the thread stuck on-CPU or blocked and its wait reason. Keep the discriminating queries and cited sample/node/thread IDs alongside the reduced finding. Show what the capture supports and what it does not.
4. **Attribute to source.** Map the hot frame to file, symbol, and line using the artifact's symbols, source maps, matching binary/debug symbols, and capture build identity. Then use source reads and available LSP symbol intelligence to inspect that location. Current code alone cannot prove the mapping for an older build. An unmapped frame is not yet a source diagnosis. Resolve symbols when available, or plainly report that the artifact lacks them and identify the missing prerequisite. OMP `debug` is a DAP live-state interface, not an arbitrary trace importer. Use its supported stack/symbol/module inspection only if a separately authorized live investigation is needed; route that work to Runtime forensics. UI-only OMP profiling/report menus are not model-callable debug actions.
5. **Confirm against a paired capture when supplied.** Convert both captures with the same method and compare equivalent workload, build, duration, sampling, and environment. Diff the relevant hot path, retained objects, or blocked-thread signature, recording both absolute and normalized changes. A before/after difference supports only the causal claim that the controls justify. Without a comparable paired capture, label the result the strongest hypothesis the artifact supports, not a confirmed cause. Do not create a new capture merely to avoid reporting that limit.
6. **Return a cited diagnosis, not an unsolicited fix.** Once the cause is known and a fix is requested, read and apply `skill://sky-mode/playbooks/bug-fix.md` or `skill://sky-mode/playbooks/perf-issue.md`. Preserve the evidence links for the handoff. Keep the throughput checkpoint to one line: `throughput checkpoint: n/a, read-only forensics`.

## Scope and evidence safety

Analyze only user-provided captures, current-task artifacts, and explicitly identified related outputs. A trace may contain credentials, URLs, document contents, or unrelated user data. Keep extracted material local and report only necessary evidence; do not upload it without authorization. For an explicitly scoped agent-session trace, use `agent://<known-id>` and `history://<known-id>` only for known relevant tasks, never arbitrary private-session discovery. Session entries form a parent-linked tree, so file order is not necessarily the executed branch. Respect reset/compaction boundaries and mark truncated or missing records. A missing transcript, symbol file, parser, paired capture, or retained blob remains an explicit limitation.

## Reply

- Artifact and format, capture identity, and analysis scope.
- Reduced finding with the decisive query or frame/node/thread evidence.
- Source file, symbol, and line, or the exact unresolved mapping.
- Original, derived database, query/output, and paired-artifact paths actually read or produced.
- Whether a comparable paired capture confirmed the finding, or why it remains a hypothesis.
- The one-line throughput checkpoint and any inaccessible-data limits.
