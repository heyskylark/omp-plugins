### Autopilot-stack

**You own the stack, never the landing. Build and verify the queue, then hand the operator one linear base-branch stack to review and land.** This is the sibling of `skill://sky-mode/playbooks/autopilot-full.md`. Read that playbook for its native owner dispatch, capacity, isolation, trail, and audit mechanics. Read and apply `skill://sky-mode`. This playbook changes landing authority, not the proof bar.

1. **Run the owner lifecycle.** Resolve the forge once. Default to `gh`; when `which origin` finds Origin and it resolves the repository, use its PR operations consistently. Otherwise record the fallback. Never require Graphite. Assign one logical OMP implementation owner per PR. Each owns build, authorized first push, a ready PR opened before self-proof, proof with gates, CI and receipts, skeptical triage via `skill://sky-mode/references/bugbot-triage.md`, `skill://deslop`, `skill://no-comments`, and the explicitly requested babysit phase via `skill://sky-mode/playbooks/babysit.md`. Apply `skill://principle-prove-it-works` and `skill://sky-mode/playbooks/opening-a-pr.md`. Only self-contained work parallelizes. Within about 15 minutes, each owner starts `decisions.tsv` through `skill://show-me-your-work`, saves the first snapshot, and, if authorized, pushes and opens the PR ready, never draft. Keep the trail uncommitted and return its artifact. Missing publication permission is an explicit gate, not permission to publish.

   Scope inline, then dispatch independent substantial owners in one bounded `task` batch with explicit shared contracts and exclusive file/branch ownership. Use configured specialist agents rather than model IDs. Skip project-wide validation during concurrent mutation. Isolate independent editing. Because native task isolation may auto-apply results, use documented `eval agent` isolation with `apply: false, merge: false` when patches must remain unaccepted or separate until verification. Retain returned agent IDs, output and patch paths before isolation teardown. One logical owner can continue in fresh bounded tasks from a consolidated brief; do not claim a worker persists indefinitely. The parent owns todo, the dependency graph and the shared notepad. No child todo or recursive orchestration.
2. **Audit on observed events and a bounded heartbeat.** Follow Autopilot-full's audit protocol roughly every 30 minutes. While the parent session is active, supervise a named `sleep 1800` process through `hub start` and observe its exit with `hub wait`; rearm after auditing. Use actual watcher processes for event wakes where available. Readiness, logs, input, cancellation and teardown use `hub`, not an invented scheduler. At each tick, re-read `skill://sky-mode/playbooks/autopilot-stack.md` and `local://<program>/notepad.md` with the full objective. Inspect an updated trunk copy only at a real known repository path. Audit the operation against both and fix drift. Inspect jobs, known agent outputs, published refs, forge changes and decision reports. Count side effects as progress, not status prose. A lane beyond its expected runtime without evidence is stuck. Stop it, reconcile artifacts and branch ownership, then dispatch a replacement. Send a status message even when unchanged. A process timer does not create agent turns after exit; ongoing work requires an active or explicitly resumed user session. Record the next audit and pickup instructions before ending.
3. **Hold the operator gates.** State-then-wait. A request for a plan is not a go. On explicit go, place the full objective, PR order, authorization boundaries and done predicate in the parent todo and scoped local notepad. On stop, send every known owner an immediate zero-writes order, cancel unsafe work, and preserve evidence. Commits, pushes, external PR writes, installations and destructive operations require their actual authorization. This mode never grants merge authority.
4. **Verify at STACK-READY.** The owner reports `STACK-READY` with exact head SHA, base SHA, stable base-to-head patch-id, current branch/base, intended parent, proof and decision-trail paths. Read and apply `skill://swarm`. The root runs independent gates, live runtime and receipts/diff audit lanes at that SHA. Use `skill://control-ui` or `skill://control-cli` for load-bearing behavior and include a regression lane against trunk or the declared parent. If the baseline lacks the feature, record it and gate the diff-added behavior and awaited end state. Cover every touched surface. Use bounded waves if the lane count exceeds actual capacity; never silently drop coverage. Aggregate one verdict. Findings return to the owner. Nothing enters the delivered stack unverified.
5. **Append on a clean verdict, never ship.** No owner or root merges, arms auto-merge, or closes a PR in this mode. A clean verdict appends the PR to one linear base-branch stack, in verified order or the operator's specified order consistent with dependencies. Do not bypass an unverified ancestor. Rebase-induced changes must pass step 7 before delivery.
6. **Single writer on topology, parallel writers on builds.** Owners write only their own branches and report tip, current base, and intended parent. The root is the sole topology writer and obtains an explicit handoff before mutating an owner's branch. Fetch the intended parent, rebase the child onto that exact tip, and verify the remote expected tip using `git ls-remote`. An authorized rewritten push uses `--force-with-lease` with that expected ref/SHA, never an unguarded force-push. If the remote differs or authorization is absent, stop that mutation and reconcile. Set the PR base to the parent branch. For authorized creation use `origin pr create --status open --base <parent-branch>` or `gh pr create --base <parent-branch>`. Retarget with `origin pr edit <pr> --base <parent-branch>` or `gh pr edit <pr> --base <parent-branch>`. Only the root PR targets trunk. No second topology owner or separate stack registry.
7. **Absorb drift at the root, then re-verify what moved.** Fetch current trunk and rebase bottom-up. Conflicts in an owner's files return to that owner as an exclusively scoped fix; the root controls subsequent topology and authorized push. Every rewritten head invalidates its old SHA verdict. Compare each verdict's stable base-to-head `git patch-id` with the new base-to-head diff. An unchanged patch-id preserves the code verdict only. A changed patch returns to step 4. Rerun current-head mergeability and CI after every rewritten push even with unchanged patch-id. Record new SHA, parent, patch-id and evidence rather than silently relabeling old receipts. Apply the countersign rule from Autopilot-full. A genuinely new pinned limit or budget raise needs fresh root proof and countersign; absorbing already-landed values is drift.
8. **Deliver the chain.** Deliver one linear verified chain, reviewable bottom-up through the selected forge. Every link carries its verifier verdict in its body or an authorized comment, or in the handoff artifact while external writes are gated. Interaction changes await operator review with screenshots and video. The operator reviews and lands it with their own clicks or merge-when-ready they explicitly arm. Retain the queue, ledger, topology generation, decision trails and exact pickup information. Do not confuse local patch application with a published or merged PR.

**Choosing between the autopilots.** Use Autopilot-full when PRs are independent and explicit landing authority is granted. Use Autopilot-stack when the operator wants review before landing, the work is coupled or sequenced, or merge authority is withheld.

**Reply:** links to the stack root and tip, ordered PRs and head SHAs, a one-line evidence-backed verdict per link, and anything parked or excluded with the reason. State clearly that nothing was merged or armed by this mode.
